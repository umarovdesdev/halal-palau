# Халал Палау — Онлайн-меню, панель управления и генератор PDF (A3 / A4 / QR)

Веб-приложение для кафе восточной кухни **«Халал Палау»**:
1. **Публичное онлайн-меню (`index.html`)** — быстрое мобильное меню для гостей, переходящих по QR-коду со столика (поиск по блюдам и составу, навигация по категориям со scroll-spy, поддержка светлой и тёмной темы).
2. **Панель администратора (`admin.html`)** — защищённый паролем редактор разделов, блюд, цен, порций, состава, текстов заведения и генератор QR-кодов для гостей.
3. **Печатное меню и карточки QR (`print.html?format=a3|a4|card`)** — вёрстка для печати с автоматическим подбором масштаба (`auto-fit`):
   - **Формат A3 (297 × 420 мм)** — всё меню целиком на **1 странице** в 3 колонки;
   - **Формат A4 (210 × 297 мм)** — всё меню на **2 страницах** в 2 колонки;
   - **Карточки QR (`format=card`)** — 4 настольные карточки формата **A6 (105 × 148 мм)** на одном листе A4 с метками реза.

---

## Быстрый старт (локальный запуск)

Требуется **Node.js 20+**.

```bash
# 1. Установка зависимостей
npm i

# 2. Запуск режима разработки (http://localhost:5173)
npm run dev

# 3. Продакшен-сборка в папку dist/ (с относительными путями base: './')
npm run build

# 4. Автоматическая сборка и генерация PDF (out/menu-a3.pdf, out/menu-a4.pdf) и PNG-превью
npm run pdf

# 5. Юнит-тесты (vitest: резервный откат, обнаружение конфликтов, таймер автоблокировки)
npm test

# 6. Проверка подключения и безопасности (RLS) базы данных Supabase
npm run db:check
```

### Страницы приложения
- `http://localhost:5173/index.html` — публичное онлайн-меню для гостей
- `http://localhost:5173/admin.html` — панель управления меню
- `http://localhost:5173/print.html?format=a3` — печатный макет A3 (1 лист)
- `http://localhost:5173/print.html?format=a4` — печатный макет A4 (2 листа)
- `http://localhost:5173/print.html?format=card` — лист A4 с 4 настольными QR-карточками A6

## Режимы работы и безопасность входа

### Безопасность панели администратора (`admin.html`)
- **Пароль никогда не сохраняется:** приложение не записывает пароль, хэш или токен сессии в `localStorage`, `sessionStorage`, `cookies` или `IndexedDB`. При каждой перезагрузке страницы или открытии новой вкладки `admin.html` пароль запрашивается заново.
- **Автоблокировка через 15 минут бездействия:** если в открытой админ-панели нет активности в течение 15 минут, экран автоматически блокируется и просит ввести пароль повторно. Все несохранённые правки при этом остаются в оперативной памяти вкладки и восстанавливаются сразу после повторного входа.

### 1. Облачный режим с Supabase (рекомендуется для публикации)
Когда заданы переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`, сайт хранит меню в облачной базе Supabase:
- Все гости видят актуальное меню сразу после нажатия кнопки **«Сохранить»** в админ-панели.
- Если проект Supabase временно недоступен или поставлен на паузу, гостевое меню автоматически и незаметно для гостей переключается на встроенный файл `menu.json` (ошибка пишется только в консоль браузера).
- Вход в `admin.html` защищён авторизацией Supabase (`persistSession: false` — сессия живёт только в памяти вкладки и автоматически завершается при закрытии страницы или нажатии **«Выйти»**). Если задана переменная `VITE_ADMIN_EMAIL`, при входе нужно ввести только пароль.
- **Защита от конфликтов при сохранении:** если меню было изменено на другом устройстве после открытия редактора, при сохранении появится встроенное предупреждение *«Меню изменили на другом устройстве — загрузить свежую версию или перезаписать?»*.
- **История версий («История версий»):** при каждом обновлении меню предыдущая версия автоматически сохраняется триггером БД в таблицу `menu_history` (хранятся последние 50 версий). В админ-панели отображаются последние 20 сохранений с датой и временем и кнопкой **«Восстановить»** (загружает выбранную версию в редактор, после чего достаточно нажать **«Сохранить»**).

### 2. Локальный режим (без базы данных)
Если переменные Supabase не заданы, сайт работает автономно:
- Начальные данные загружаются из `./menu.json`, а правки в админ-панели сохраняются в `localStorage` браузера (`halal_palau_menu_v1`).
- Вход в `admin.html` защищён проверкой PBKDF2-хэша пароля (600 000 итераций, соль; `VITE_ADMIN_PASSWORD_HASH` или константа `ADMIN_PASSWORD_HASH` в `src/admin/auth.ts`, новый хэш: `node scripts/hash-password.mjs`), состояние входа хранится только в памяти React.

## Публикация на GitHub Pages + Supabase

Пошаговая инструкция для запуска сайта и онлайн-редактора меню (бесплатно, без платных серверов):

### Шаг 1. Настройка базы данных Supabase (`supabase/schema.sql`) и администратора
1. Зарегистрируйтесь на сайте [supabase.com](https://supabase.com) и нажмите **New project** (создайте новый проект на бесплатном тарифе Free).
2. В левом меню откройте **SQL Editor**, создайте новый запрос (**New query**), вставьте в него всё содержимое файла [`supabase/schema.sql`](./supabase/schema.sql) и нажмите **Run**. Скрипт идемпотентен (его можно безопасно запускать повторно) и настраивает:
   - таблицу `public.menu_documents` (`id`, `data`, `updated_at`) с триггером автообновления `updated_at`;
   - таблицу `public.menu_admins` — список администраторов; писать меню может только пользователь из неё (не любой вошедший в Supabase);
   - политики безопасности **RLS** на `menu_documents`: публичное чтение (`SELECT`) для всех, добавление и обновление (`INSERT`/`UPDATE`) только для администраторов из `menu_admins`, политика удаления (`DELETE`) отсутствует;
   - таблицу `public.menu_history` (`id`, `menu_id`, `data`, `saved_at`, `saved_by`): читать могут только администраторы, пишет только триггер, который при каждом обновлении `menu_documents` сохраняет предыдущую версию и оставляет последние 50.
3. В левом меню откройте **Authentication → Users** и нажмите кнопку **Add user → Create new user**:
   - Введите **Email** и **Password** (пароль, которым вы будете входить в панель управления меню).
   - Обязательно оставьте включённой галочку **Auto Confirm User** и нажмите **Create user**.
   - Добавьте этого пользователя в администраторы: в **SQL Editor** выполните (подставьте свой email):
     ```sql
     insert into public.menu_admins (user_id)
     select id from auth.users where email = 'admin@example.com'
     on conflict do nothing;
     ```
   - Закройте регистрацию посторонним: **Authentication → Sign In / Providers → Email** — выключите **Allow new users to sign up**.
4. В левом меню откройте **Project Settings** (иконка шестерёнки внизу) → **API** и скопируйте два значения:
   - **Project URL** (адрес вида `https://xxxxxxxx.supabase.co`)
   - **Project API Keys → `anon` `public`** (длинный публичный ключ)

### Проверка базы данных из терминала (`npm run db:check`)
Для локальной проверки подключения к Supabase и работы политик безопасности RLS создайте в корне проекта файл `.env` (он не попадает в сборку без вашего ведома):
```env
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=ваш_anon_public_ключ
VITE_ADMIN_EMAIL=admin@example.com
```
Затем выполните:
```bash
npm run db:check
```
Скрипт [`scripts/db-check.mjs`](./scripts/db-check.mjs):
- без файла `.env` подскажет, как его создать, и завершится с кодом `0`;
- при наличии `.env` выполнит анонимное чтение записи `id='main'` из `menu_documents`, проверит, что анонимный `UPDATE` **отклоняется** правилами RLS, и выведет `OK: меню в базе, N позиций, обновлено …` либо понятную подсказку на русском языке (если таблица не создана — *«выполните supabase/schema.sql»*, если начальное меню ещё не загружено — *«войдите в админку и нажмите "Загрузить начальное меню"»*).

### Шаг 2. Публикация кода на GitHub и настройка секретов
1. Создайте новый репозиторий на [github.com](https://github.com) (например, `halal-palau-menu`) и загрузите (push) в него код проекта в ветку `main`.
2. В репозитории на GitHub откройте вкладку **Settings → Pages** (в левом меню):
   - В блоке **Build and deployment** в выпадающем списке **Source** выберите **«GitHub Actions»**.
3. В том же меню **Settings** откройте **Secrets and variables → Actions**:
   - Во вкладке **Secrets** нажмите **New repository secret** и добавьте два секрета:
     - `VITE_SUPABASE_URL` — вставьте скопированный **Project URL** из Supabase;
     - `VITE_SUPABASE_ANON_KEY` — вставьте скопированный ключ **`anon` `public`** из Supabase.
   - Переключитесь на вкладку **Variables**, нажмите **New repository variable** и добавьте переменную:
     - `VITE_ADMIN_EMAIL` — укажите Email администратора, который вы создали в Supabase (тогда при входе в админку нужно будет вводить только пароль).

### Шаг 3. Запуск сборки и первичная загрузка меню
1. Перейдите во вкладку **Actions** вашего репозитория на GitHub:
   - Если сборка **Deploy to GitHub Pages** ещё не запустилась или была запущена до добавления секретов, выберите её слева и нажмите **Run workflow → Run workflow** (или **Re-run all jobs**).
   - Подождите 1–2 минуты, пока кружок рядом со сборкой станет **зелёным (✓)**.
2. После успешной сборки ваш сайт опубликован:
   - **Гостевое онлайн-меню:** `https://<ваш-логин>.github.io/<имя-репозитория>/`
   - **Панель управления:** `https://<ваш-логин>.github.io/<имя-репозитория>/admin.html`
3. Откройте панель управления (`.../admin.html`), введите ваш пароль администратора и нажмите **«Войти»**.
4. При самом первом входе нажмите кнопку **«Загрузить начальное меню»** в верхней полосе панели управления — это скопирует все исходные блюда и разделы в облачную базу Supabase.
5. Теперь вы можете менять цены, добавлять и скрывать блюда и нажимать **«Сохранить»** — изменения сразу же появятся у гостей.

### Шаг 4. QR-код для гостей и печать настольных карточек
1. В панели управления (`admin.html`) найдите блок **«QR-код для гостей»** — адрес опубликованного сайта определяется автоматически (при желании вы также можете задать свой домен в поле `URL онлайн-меню для QR-кода`).
2. Доступные действия в блоке **«QR-код для гостей»**:
   - **«Скачать PNG»** — сохраняет чёткий QR-код высокого разрешения (`1024 × 1024 px`, тёмный код `#1D1A17` на белом фоне с защитным полем) для отправки дизайнеру или в типографию;
   - **«Скачать SVG»** — сохраняет векторный QR-код любого масштаба;
   - **«Копировать ссылку»** — копирует прямую ссылку на онлайн-меню;
   - **«Карточка на стол (печать)»** — открывает страницу `print.html?format=card`, где на одном листе A4 расположены **4 одинаковые карточки формата A6 (105 × 148 мм)** с логотипом, названием кафе, QR-кодом и подписью на казахском и русском языках и тонкими линиями разреза. Нажмите **«Скачать PDF»** (поля: *Нет*, фоновая графика: *Включить*), распечатайте лист A4 и разрежьте по пунктирным линиям.
3. На печатных макетах **A3 (`print.html?format=a3`)** и **A4 (`print.html?format=a4`)** в подвале также автоматически размещается QR-код с подписью *«Мәзір онлайн · Меню онлайн»*.
